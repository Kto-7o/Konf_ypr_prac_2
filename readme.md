# Практическая работа 2, вариант 9

## Инструмент визуализации графа зависимостей пакетов Ubuntu (apt)

## 1. Общее описание

Консольное (CLI) приложение на **Python** для построения и визуализации
графа зависимостей пакетов Ubuntu. Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются.

Реализованные этапы:

1. **Минимальный прототип с конфигурацией** — все параметры задаются в
   YAML-файле, при запуске выводятся в формате «ключ = значение»,
   ошибки во всех параметрах обнаруживаются и описываются.
2. **Сбор данных** — загрузка индекса пакетов Ubuntu (apt) по URL,
   поиск заданной версии пакета и вывод всех его прямых зависимостей.
3. **Основные операции** — построение графа зависимостей с учетом
   транзитивности обходом в ширину (BFS) без рекурсии, фильтрация
   пакетов по подстроке, обработка циклических зависимостей, режим
   тестового репозитория.

## 2. Описание функций и настроек

### Параметр командной строки

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `-c`, `--config PATH` | `config.yaml` | Путь к YAML-файлу конфигурации |

### Параметры конфигурации (YAML)

| Ключ | Тип | Описание и проверки |
|------|-----|---------------------|
| `package` | строка | Имя анализируемого пакета. Обычный режим: строчные латинские буквы, цифры, `+ . -`, не короче 2 символов (правила Debian). Тестовый режим: только большие латинские буквы |
| `repository` | строка | Обычный режим: URL файла `Packages` (`.gz`/`.xz`) со схемой `http`, `https` или `file`. Тестовый режим: путь к существующему файлу тестового репозитория |
| `test_mode` | `true`/`false` | Режим работы с тестовым репозиторием |
| `version` | строка | Версия пакета в формате Debian (`[эпоха:]версия[-ревизия]`), начинается с цифры. Числа вида `1.0` нужно заключать в кавычки |
| `output` | строка | Имя файла с изображением графа, расширение `.png`; каталог должен существовать |
| `filter` | строка | Необязательный. Подстрока: пакеты, имя которых ее содержит, не учитываются. По умолчанию пустая строка |

Пример `config.yaml`:

```yaml
package: curl
repository: http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz
test_mode: false
version: "8.5.0-2ubuntu10"
output: graph.png
filter: ""
```

### Обработка ошибок

Проверяются: наличие и читаемость файла, синтаксис YAML, то, что корень
документа — набор «ключ: значение», отсутствие обязательных и наличие
неизвестных параметров, тип и значение каждого параметра. Сообщается
сразу обо всех найденных ошибках (строки `Ошибка конфигурации: ...` в
stderr), код возврата — `1`.

### Получение зависимостей (формат Ubuntu / apt)

Параметр `repository` — URL индексного файла `Packages` одного
компонента репозитория, например
`http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz`.
Индекс загружается стандартным модулем `urllib` (поддерживаются схемы
`http`, `https`, `file`), распаковывается (`gzip`, `xz` или без сжатия)
и разбирается вручную: блоки «Поле: значение», разделенные пустыми
строками, с учетом строк-продолжений. Менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются.

Для пакета `package` выбирается блок с полем `Version`, равным
`version`; прямые зависимости — записи полей `Pre-Depends` и `Depends`
(через запятую). Для остальных пакетов графа берется первая версия из
индекса. Из альтернатив `a | b` учитывается первая (ее выбирает apt).
Виртуальный пакет (например, `libgnutls30`) заменяется пакетом,
который его предоставляет через поле `Provides` (`libgnutls30t64`).
Пакеты, отсутствующие в индексе (например, из другого компонента
репозитория), считаются пакетами без зависимостей и перечисляются в
конце отчета.

Ошибки (stderr `Ошибка репозитория: ...`, код возврата `1`): сервер
недоступен или вернул ошибку HTTP, поврежденный архив, пустой индекс,
пакет не найден, версия не найдена (выводится список доступных версий).

### Построение графа (этап 3)

- Граф строится обходом в ширину (`collections.deque`) без рекурсии:
  каждый пакет попадает в очередь один раз, поэтому общие и
  циклические зависимости обрабатываются корректно и без зацикливания.
- Пакеты, имя которых содержит подстроку `filter`, не учитываются
  (вместе с зависимостями, достижимыми только через них). Если
  подстроку содержит сам анализируемый пакет, граф пуст.
- Циклы находятся итеративным обходом в глубину и выводятся строками
  `Циклическая зависимость: A -> B -> C -> A`.

### Режим тестового репозитория

При `test_mode: true` параметр `repository` — путь к текстовому файлу
с описанием графа; пакеты называются большими латинскими буквами,
параметр `version` не используется:

```
# комментарий
A: B C      # A зависит от B и C (разделитель - пробел или запятая)
B: D
D:          # пакет без зависимостей
```

Ошибки формата (нет двоеточия, недопустимое имя, повторное описание
пакета) сообщаются с номером строки. Пакет, на который есть ссылка, но
нет описания, считается пакетом без зависимостей. Примеры — в `repos/`:

| Файл | Что демонстрирует |
|------|-------------------|
| `simple.txt` | ромб без циклов (общая зависимость `E`) |
| `cycles.txt` | цикл `A→B→C→A`, петля `D→D`, цикл `E→F→E` |
| `complex.txt` | фильтр `LIB`, неописанный пакет `DRIVER` |
| `broken.txt` | ошибка формата |

### Модули

- `config.py`: `Config`, `ConfigError`, `load_config()`.
- `apt_repo.py`: `load_index()`, `parse_index()`, `parse_depends()`,
  `find_package()`, `direct_dependencies()`, `build_provides()`,
  `AptSource`, `Dependency`, `RepositoryError`.
- `local_repo.py`: `load_local_repo()`, `parse_local_repo()`,
  `LocalSource`.
- `graph.py`: `build_graph()` (BFS), `find_cycles()`, `format_graph()`.
- `main.py`: `build_parser()`, `make_source()`, `report()`, `main()`.

## 3. Сборка и запуск тестов

Требуется **Python 3.8+**, **PyYAML** и **pytest** (≥ 7):

```bash
pip install pyyaml pytest
python3 -m pytest -v
```

Запуск приложения:

```bash
./run.sh [--config FILE]          # Linux / macOS
run.bat [--config FILE]           # Windows
python3 src/main.py [--config FILE]
```

Демонстрационные скрипты:

```bash
bash scripts/demo_config.sh       # ошибки конфигурации (этап 1)
bash scripts/demo_graph.sh        # тестовые репозитории (этап 3)
bash scripts/demo_ubuntu.sh       # репозиторий Ubuntu (этап 3)
```

Для Windows — одноименные `.bat`-файлы в `scripts/`.
